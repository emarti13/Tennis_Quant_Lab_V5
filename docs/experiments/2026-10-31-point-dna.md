# Point DNA (shot-by-shot style) against the market: no added information

Date: 2026-10-31. Research only; pre-2026 data (the sealed period is untouched).
Script: `research_tests/point_dna/run_point_dna.py`; full output: `research_tests/point_dna/results.json`.

## Question

The user wants point-level detail (rally length, shot types, how points end, serve direction):
"the DNA of the point". results.tennisdata.com shows it per match, but it is behind a
Cloudflare bot check and appears to be Tennis Data Innovations' licensed data; it was not
scraped. The Tennis Abstract Match Charting Project (CC BY-NC-SA 4.0, research use;
github.com/JeffSackmann/tennis_MatchChartingProject) has the same kind of data in more detail:
7,566 men's and 4,264 women's matches, about 600-800 men's matches a year since 2022, mostly
Slams and Masters, almost no Challengers. Does a player's charted style add information
beyond the market?

## Method (pre-registered in the script's docstring before any result)

- Profiles: per player, the charted matches in the 3 years before the tournament's start
  (none from the same tournament), half-life 1 year, at least 5 matches; rates shrunk toward
  pre-2014 charted means (200 points). 31 rates: serve (aces, double faults, first serve in and
  won, second serve won, unreturned, won in 3 shots or fewer, wide/T shares, direction
  entropy), return (vs first and second serve, in play, vs wide and vs T serves), rally length
  (won share of 1-3, 4-6, 7+ shot points, share of long rallies), net (frequency, won), winners
  and unforced errors (forehand, backhand), break points saved.
- Matchup features: A-minus-B differences and interactions (serve aimed at the opponent's
  weaker return side, rally-length matchup, serve power vs return reliability, net rusher vs
  passer, left-hander vs the opponent's wide-return weakness).
- Matches: the Kaggle odds join (2014-2025), both players profiled; 15,728 test rows
  (2018-2025), 11,896 in the primary set (ATP and WTA main tours, 2021-2025).
- M0 = logistic on logit(Betfair closing, de-vigged); M1 = M0 + DNA (L2 logistic); M1gb =
  LightGBM. Walk-forward by year from 2015. Log loss, match bootstrap.

## Results

| Comparison | n | log loss change (M1 − M0) | 95% range |
|---|---|---|---|
| PRIMARY: DNA on top of Betfair close, main tours 2021-25 | 11,896 | **+0.0014 (worse)** | +0.0005 to +0.0024 |
| LightGBM version | 11,896 | +0.0051 (worse) | +0.0034 to +0.0068 |
| On top of bet365's open (softer price), main tours 2021-25 | 11,772 | +0.0013 (worse) | +0.0003 to +0.0023 |
| Without the market: DNA vs plain serve/return rates | 15,728 | −0.0075 (better) | −0.0113 to −0.0036 |

Without the market, DNA predicts better than plain serve and return rates, but far worse than
the market: 0.660 against Betfair close 0.607. Added to the market, it makes things worse in 4
of 5 primary years (2023: −0.0002). Betting at Betfair close (2% commission) and at bet365's
open, edge thresholds 3/5/8 points: every cell's return is negative or has a range including
zero (e.g. Betfair close, logistic, edge ≥ 3 pts: −6.6%, n=1,656).

**Verdict: no information beyond the market. The market already prices playing style.**

## A leak found and fixed during the run

The first run showed LightGBM "beating" bet365's open by 0.058 log loss with +33-53% returns.
The cause was this script, not the data: the flipped side's probability was written as `1 - p`,
whose float rounding differs from computing it from the swapped odds. With bet365's few
distinct ladder prices, LightGBM split on those last-digit differences and read the winner.
Fixed by computing every row's probability from A's and B's odds the same way. The earlier
Kaggle tests (`kaggle_market`, `totals_market`) orient the odds before computing
probabilities, so they do not have this leak (checked in the code).

## What would change the verdict

- Challenger coverage: the charting data has almost none; the market there is thinner. It
  would need licensed data (Tennis Data Innovations) or our own collection.
- In-play: point detail may matter more within a match than before it. Testable with the
  server's live logs (point score and running stats every 10 s), not with this data.

## Re-run on the research toolkit with the general checks (same day)

The user challenged the verdict. The test was rebuilt on `research_kit` (see
`research_kit/README.md`) and every check was run. An independent agent also re-implemented v1
from the written spec without reading this code: +0.00117 (range +0.00019 to +0.00217), n=11,896,
market log loss 0.60401, against this script's +0.00145. They agree within noise.

| | v1 (39 features, as first run) | v2 (8 features, pre-registered after v1's checks) |
|---|---|---|
| swap-source / time-travel / shuffled / known answers | pass / pass / pass / pass | pass / pass / pass / pass |
| Market-null cost (features carry nothing by construction) | **+0.0017** (+0.0007 to +0.0027) | −0.0001 (−0.0005 to +0.0003) |
| Planted edge (true improvement 0.0064) recovered | 0.0035 (55%) | 0.0053 (83%) |
| PRIMARY: on top of Betfair close, main tours 2021-25 | +0.0015 (+0.0005 to +0.0024) | **+0.0005 (−0.0001 to +0.0010)** |
| On top of bet365's open, main tours 2021-25 | +0.0013 | +0.0004 (−0.0002 to +0.0010) |
| bet365 open→close moves toward what DNA adds | 5.7% of it (3.5 to 8.0%) | 8.3% of it (4.3 to 12.2%) |

v2 is the compact set chosen in advance: serve points won, return points won, unreturned serves
(aces + untouched + forced return errors; v1's `unret` counted only untouched serves, flagged by
the independent agent's low prior mean), short- and long-rally win rates, serve aimed at the
opponent's weaker return side, rally-length matchup, serve power against return reliability.

**What changed:** v1's "worse than the market" was mostly the cost of fitting 39 noisy features,
as the market-null check shows; the first write-up's "the market already prices style" read too
much into it. **What did not:** with the stronger v2 test (no fitting cost, 83% of a planted edge
recovered), style still adds nothing measurable on top of Betfair's close; the range rules out a
gain bigger than about 0.0001. Style does carry information the bet365 OPEN lacks (the close
moves 5-12% of the way toward it), about 0.3 points of price on the biggest disagreements: real
but far below bet365's margin. Whether that matters at a low-fee venue's opening prices is
untested (no Kalshi history overlaps the charting data's coverage before the sealed period).

Betting cells moved between runs with only the orientation seed changed (e.g. Betfair close,
edge ≥ 5 pts: −8% then −15%): betting returns on a few hundred bets are noise at this size.
